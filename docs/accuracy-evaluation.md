# 准确率与延迟评测

两遍方案的目标是兼顾及时反馈和最终结果，不承诺第二遍永远更准确。当前第二遍重新识别音频，最终只采用 SenseVoice 结果；没有置信度融合，也没有大语言模型纠错。

## 已有自动测试

`tests/fixtures/` 是无个人信息的合成语音，包括三句普通话、一句英语和一句中英混说。实际端侧 instrumentation 复用 `TwoPassStream`，检查：

- 定稿之前出现临时文字。
- 停顿后正常分句。
- stop/flush 提交最后一段。
- 两句依次输出，没有合成一个错误段。
- 静音不输出定稿。

合成语音适合发现代码和模型加载回归，不能代替真实口音、噪声和现场准确率。测试结果中的 `first_partial_audio_ms` 是喂入多少毫秒音频后出现第一份初稿，数据以最快速度送入，不是麦克风端到端墙钟延迟。静音项的 partial_changes 为 0，不能解读其时间字段。

## 建议的真人参考集

开始收集前取得说话者授权，录音只在明确批准的本地位置管理，不放进 Git。选同一批参考音频比较三个输出：

1. 流式初稿在句末的结果。
2. SenseVoice 独立处理完整参考句的结果。
3. 真实两遍路径经过 VAD 分段后的最终结果。

第 2 与第 3 项的差异有助于定位 VAD 切掉字头/字尾、长句强制切分或采样链路问题，避免把全部错误归因于模型。

覆盖普通话、纯英语、句内混说；短指令、长句、数字/日期、人名/产品名、低音量、背景人声、距离变化。对用户频繁说的词单独统计，但不要只拿少量固定句反复调参后宣称通用准确率。

## 指标

- 中文 CER：编辑距离 / 参考字符数。明确是否忽略标点、空格以及如何归一化数字。
- 英文 WER：词级替换、删除、插入之和 / 参考词数。明确大小写、缩写和数字的归一化规则。
- 混说：中文 CER、英文词错误和关键实体错误分别报告；不要把不同分词方式合成一个难解释的百分比。
- 延迟：从真实开口到首次有效临时文字、从实际句尾到定稿的 P50/P95，包含等待停顿的时间。
- 运行：峰值 RSS、持续 CPU、队列积压、热量、电量和丢样情况。
- 生命周期：录音中断、快速开始/停止、切后台、关闭界面、取消后立即开始。

## 迭代顺序

先确认采样率、音量、削波、设备路由和分段完整性；再用同一数据评估语言设置和停顿阈值；最后对比其他流式/最终模型。热词能力需要针对所选模型和解码器单独实现验证，当前 API 没有提供热词接口。

如果增加第三层文本润色，应与忠实转写明确分开，由用户选择；不要悄悄把原话改成看似更通顺但含义不同的文本。
